Evolving Excellence: Automated Optimization of LLM-based Agents

arXiv

Narrated explainer, a little over three minutes. The voice is synthetic. All numbers are the ones reported in the paper; the search tree and the grid of combinations are schematic.

The problem

An agent built on a language model is a pipeline, and it has a configuration: prompts, tool descriptions, the choice of models, and numerical parameters such as temperature and timeouts. Small changes to any of these can change performance a lot, and the parts interact. Tuning them by hand typically takes weeks.

As a search problem it is awkward. The space mixes text, discrete choices and real numbers. There are no gradients. One evaluation is a full benchmark run, which can take minutes to hours. Different prompting strategies give different local optima. And a random edit of a prompt is usually meaningless.

The approach

Artemis treats the agent as a black box. It needs the code, a benchmark script and a goal in plain language. It finds the components that can be tuned, and it uses the benchmark results and the execution logs as feedback. The agent's architecture is not changed.

The search is a genetic algorithm whose operators are language models. A mutation rewrites a component and keeps it meaningful, and a crossover merges what worked in two candidates. Evaluation is hierarchical: cheap checks, such as scoring by a language model, filter most candidates, and only the promising ones are run on the real benchmark.

There are two strategies. Local optimization evolves each component on its own, which suits components that do not interact much. Global optimization uses Bayesian optimization to search over combinations of component versions, for the cases where components only work well together.

The results are mixed in an informative way. The ALE improvement is not statistically significant. For the CrewAI agent the lower token cost came with a drop in accuracy, from 0.82 to 0.76. The search is expensive: the ALE experiments took 671.7 hours of computation in total. Automated tuning helped most where the starting configuration was weak and the metric was clear.

What we take from it

An agent's configuration can be optimized automatically, as a black box, with no change to its architecture and no hand-written fitness function. Where there was room to improve, the gains were substantial, and where accuracy was already high the cost could be cut instead. The method worked for commercial models and for a small open-source model run locally. Tuning an agent can be a search, not weeks of trial and error.
